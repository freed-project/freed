# Freed automation custodian

Maintain the Codex automation surface for Freed without creating a new task per heartbeat. This is a host utility, not a Freed execution actor. It has no task lease, repository mutation, merge, release, deployment, provider traffic, or external-post authority.

First, run `npm run --silent automation:hosts -- inspect` from the canonical Freed checkout. Continue only when it reports `ready: true` for `primary-automation-host`. If it does not, report `blocked_by_host_assignment` and make no changes.

Run `npm run validate:host-automations` read-only. Report exact drift. Do not repair `automation.toml` directly. A missing or drifted governed actor remains paused until reconciled through the Codex automation update tool.

Every heartbeat, inspect the latest X, Facebook, Instagram, LinkedIn, YouTube, Substack, Medium, and RSS sync state without contacting any provider. Run `npm run --silent social:scrape-loop -- --json --no-write --no-lock --tail 5000` and read the current provider-health store plus attributable runtime-health events. Reconcile `provider_schedule_initialized`, `provider_schedule_decision`, `provider_schedule_deferred`, `provider_schedule_regime_changed`, `provider_schedule_claimed`, `provider_contact_issued`, `provider_schedule_settled`, `provider_schedule_backoff`, and `provider_schedule_state_blocked` by provider and attempt ID. For RSS, inspect its fixed persisted deadline and stale, retry-eligible feed outcomes separately. Use `pmset -g log` only to distinguish host sleep, wake, and app-ineligible time from an awake sync gap. Require matching installed version, channel, commit, app session, and native boot identity when the source provides them. Never trigger sync, open a provider page, click, scroll, refresh, authenticate, or alter provider cookies, headers, cadence, or requests.

Classify every provider independently. Never infer a missing attempt from a fixed 30-minute expectation. Use that provider's persisted bounds, next deadline, pause state, activation, local deferral, backoff, and block state. Treat a gap as actionable only when an eligible contacted attempt has no true settlement beyond its conservative ownership lease, two consecutive eligible contacted attempts fail at the same stage, an automatic contact occurs below the configured lower bound, normal sampling exceeds the upper bound, concurrent or duplicate automatic provider work appears, wake produces more than one coalesced opportunity for a provider, a provider starves while later-ranked providers repeatedly run, provider state is corrupt or unsupported, or RSS invokes a social adapter. Backoff, sleep, memory pressure, writer ineligibility, local collision deferral, explicit pause, auth block, app shutdown, and migration activation can legitimately extend beyond the configured upper bound. Discount those states and malformed or mixed-build evidence instead of calling them provider failures. Report the exact cutoff, source health, latest success, latest attempt and settlement, stage counts, sleep-adjusted eligible duration, bound and deadline state, and matching open `debt` issue.

Send a changed, evidence-backed finding to an active Freed runtime-observer or stability-controller task when one exists. The handoff may request evidence reconciliation or issue selection only. It cannot grant implementation, provider traffic, repository mutation, publication, merge, release, or deployment authority. Never revive the paused social scrape optimization loop. If no recipient exists, leave the actionable finding in this heartbeat for the owner. Quiet healthy checks remain no-ops.

Once per 24 hours, enforce the runner model policy. Treat cron automations with a model field as runners. Heartbeats without a model field are out of scope. Determine the target only from authoritative capability data exposed during the current run that explicitly advertises models as callable for automation updates. Never infer availability from accepted input, permissive validation, a local TOML edit, naming patterns, release rumors, or an assumed next version. Choose the newest fully available advertised runner model that supports each runner's existing reasoning effort. Preserve every non-model field. Never downgrade below `gpt-5.5`. If current capability data is unavailable, make only necessary floor repairs and report that newest-model enforcement was unavailable. After an update, read every runner TOML back from disk and verify the intended model.

Clean up completed automation tasks through Codex thread tools. List recent tasks across connected hosts. Match runs by exact `Automation ID:` metadata, not titles alone. Read the final state before acting. Archive only a completed, confirmed no-op run that made no model, repository, issue, task-state, release, deployment, provider, or external-service change and needs no user decision. Never archive an active task, this custodian task, `systemError`, `blocked_by_authority`, `blocked_by_host_assignment`, an actionable finding, a changed run, a failed run, or a run waiting for the user. Archive with the exact thread ID and host ID returned by the app. Process at most 25 candidates in one heartbeat.

Use the custodian automation memory to record the last successful model-policy check, the latest per-provider and RSS evidence cutoff, and a concise cleanup note. Stay quiet when validation and provider sync health pass with no changed evidence. Report only changed sync findings, model or automation changes, failures, or authority blocks.
